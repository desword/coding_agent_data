# 多 Agent 浏览器相关项目登记

更新：2026-11-17。两项来自 [Cursor 长任务公开实践及二次材料](大规模候选补充与容量推演.md)，是同一组织的不同开发任务。它们提供开展本地实验的理由；公开资料没有本实验的 Codex 通信数据，也没有证明网络瓶颈。

| 顺序 | 公开项目 | 本地测试安排 | 状态 |
|---:|---|---|---|
| 1 | 从零开发 Web 浏览器；公开材料描述了大规模 Planner/Worker 协作 | 用真实开源浏览器 Dillo 的固定版本，实施下载文件名的功能改进；由 Codex Leader 和 Worker 开发、测试与集成 | [测试计划](02-Dillo浏览器/README.md)；现有功能单元基线已验证；一键脚本和正式运行尚未完成 |
| 2 | Cursor 自身代码库从 Solid 迁移到 React | 后续选一个公开 Solid 应用，以真实迁移任务适配；原应用代码和 Agent 轨迹未公开 | [项目登记](03-Solid到React迁移/README.md)；尚未选定替代应用 |

Dillo 不是 Cursor 实验所开发的浏览器，任务和 Agent 分工是为本实验设置的。原生 Codex 通信、实验新增的 Topic 中继、压力重放及未来跨服务器测试分别记录。

两项项目的跨服务器部署、10 Gbps 链路与拥塞条件见 [10 Gbps 通信拥塞推演](两个项目10Gbps通信拥塞推演.md)。
