# 房间预订 API 之后：10 个具体应用备选

更新时间：2026-11-16。首测为 [房间预订 API](01-房间预订API/README.md)；下列应用供后续测试，均为具体软件项目或明确的应用开发任务，不是单独的 Agent 框架。

本轮新发现 **8 项**，另将前轮已找到的 **2 项**重新核对并补入清单，凑齐 10 个独立应用。所有项目的“高并发导致通信瓶颈”仍需实际测试：当前没有公开证据能直接证明。优先级按具体任务、Leader/Worker 证据、可获取记录和轻量运行条件排序，不按项目人气或未经验证的流量大小排序。

## 1. AI 星座图网站

具体交付物是用 Three.js 展示 X 上 AI 模型话题的 3D 网站。[项目 README](https://github.com/fujibee/agmsg-demo-fable5-x-constellation/blob/cae69075eb85402fed00cf4b6c747f14bbc1e6e4/README.md)称 Fable/Claude Code 负责设计与最终审查，Opus 实现，Codex 完善画面，Grok 收集数据；[完整团队对话](https://github.com/fujibee/agmsg-demo-fable5-x-constellation/blob/cae69075eb85402fed00cf4b6c747f14bbc1e6e4/TRANSCRIPT.md)提供任务分配、Worker 直接交接和返工信息。

本轮统计该英文对话文档有 24 条带时间的条目：20 条 Agent 间、4 条涉及人类；时间从 18:20:13 到 19:09:25。记录包含 Worker 之间直接交接，不是全经 Leader。它适合作为真实对话内容和角色路由的基线；记录条数不等于网络包数，不证明压力。

## 2. 说剑游戏

[说剑 README](https://github.com/xxxxxthhh/shuojian/blob/0f3d7888df0cd57bae6f00b7f3cd5db765ded93a/README.md)描述浏览器水墨横版游戏，作者称 Claude Code Agent Team 按引擎、美术、音频、剧本、战斗、敌人和关卡七路并行，后续再分工修复。[接口契约](https://github.com/xxxxxthhh/shuojian/blob/0f3d7888df0cd57bae6f00b7f3cd5db765ded93a/_spec/CONTRACTS.md)要求跨范围接口变更报告 Lead；[Lead 评审](https://github.com/xxxxxthhh/shuojian/blob/0f3d7888df0cd57bae6f00b7f3cd5db765ded93a/_spec/REVIEW.md)记录回归、返工及最终结果。

它的多模块和持续接口变更适合依赖/分发实验；项目报告任务分工，不提供完整通信流量。游戏在浏览器中运行，服务器资源占用仍需测。

## 3. 餐饮网站迁移

[餐饮网站](https://github.com/HuiyuLiz/ai-driven-dining-system/blob/e8d772a45035b3408ca2316edb364bc6c61251ff/README.md)从 React/Vite 迁移到 Next.js。作者明确描述 Claude Code 的五个并行 Agent，分别处理脚手架、组件、布局、首页和其他页面；team lead 协调依赖、样式迁移和构建错误。

共享组件及页面依赖适合测试任务触发和集成。原项目没有公开逐消息速率，跨服务器和订阅需另行设计。

## 4. 交易前准备应用

[Market Preparation Assistant](https://github.com/leoniex1/market-prep-agent-teams/blob/65924f552d02a2123fed064e30e1c3923fc4fdda/README.md) 是交易前检查的 Web 应用，不执行交易；[团队契约](https://github.com/leoniex1/market-prep-agent-teams/blob/65924f552d02a2123fed064e30e1c3923fc4fdda/CONTRACTS.md)列出 backend、frontend、AI、QA 和 team lead 的所有权及共享类型。应用有无密钥的确定性响应路径，适合作为较轻量的业务基线。

项目是 Claude Code Agent Teams 与另一开发方式的对比练习；没有可用的 Leader 网络吞吐数据。应用内聊天请求属于业务流量，不是开发 Agent 通信。

## 5. Oura 商家管理

[Oura 项目](https://github.com/williamxdferney2002-rgb/Business-oura-sistema/blob/a80b5d2fc31d19a9a7cf8d932c2e9722dc74744/README.md)描述小商家库存、销售和 Telegram 业务系统；[开发协议](https://github.com/williamxdferney2002-rgb/Business-oura-sistema/blob/a80b5d2fc31d19a9a7cf8d932c2e9722dc74744/docs/02-multi-agent-system.md)说明 Claude Code 作为架构/协调者，Codex 执行，独立会话审计，失败后可重新分配修复。作者报告 31 个任务，并描述后期 Claude 调用 Codex 的方式。

公开仓库只提供文档与模板，不含生产代码；业务系统和任务只能按公开材料自行实现或适配。流程含人工审批和顺序阶段，未证明高并发。

## 6. SecureAuthKit 验证应用

[SecureAuthKit](https://github.com/YangJinmo/SecureAuthKit/blob/c7e73731f01db30a5ab305cd51ef13b4f94f4ebb/README.md) 包含认证 SDK 和 SwiftUI 演示应用。[作者的公开案例](https://github.com/YangJinmo/claude-code-case-studies/blob/1450df66c51bdb7f7b5e1d9a97fc0a1c7498cb31/README.md)称依据 Claude Code 会话日志统计：8 个任务、19 个实现/审查子 Agent；最终集成审查发现并修复多项问题。

作者的汇总是实际开发证据，原始完整日志没有在本次找到。SDK 可在 macOS 直接测试，完整 iOS 演示涉及模拟器；不能假设此项目在扩大并发时网络会先于设备资源饱和。

## 7. PartMoney 工资记录

[PartMoney](https://github.com/YangJinmo/PartMoney/blob/db92721ba348053ff1af8a2c372e5b24d9ad0fa8/README.md) 是 SwiftUI 排班和收入记录应用。[同一作者的案例汇总](https://github.com/YangJinmo/claude-code-case-studies/blob/1450df66c51bdb7f7b5e1d9a97fc0a1c7498cb31/README.md)称曾在 PartMoney 等项目使用 Claude Code 并行代码审查，每会话 15 个子 Agent，并以额外 Agent 交叉核查。

适合研究短时间审查结果汇合；它与 SecureAuthKit 同作者，不能当作独立组织验证。iOS 目标测试需要 Xcode/模拟器，不能假设模拟器不是瓶颈。

## 8. arXiv 阅读器

[公开教学项目](https://github.com/kevin801221/claude-code-agent-team-tutorial-iosApp/blob/a89435c31e8425624914fa103c7170cd24f33ece/README.md)规定开发 Flutter 阅读器和 Python 后端：team lead 冻结接口并集成，三个 Worker 分别负责后端、阅读界面和休息提醒，共享任务清单和 mailbox。

作者明确说明仓库是让读者自行构建的教材，不是已经完成的应用运行轨迹。它是**可执行的公开任务定义**，不是已实测多 Agent 流量。前端和模型 API 依赖可能限制并发，需先测资源。

## 9. Factory4X 游戏

[Factory4X 流程](https://github.com/tQuarella/factory4x/blob/b3f40f31935830ea5d7eec036c606a3ced924c1d/PROCESS.md)规定 Claude Code Director、并行工程师、Critic、依赖和合并；[状态记录](https://github.com/tQuarella/factory4x/blob/b3f40f31935830ea5d7eec036c606a3ced924c1d/STATUS.md)有任务启动、审核和修复实例。它是前轮已找到的项目，本轮重新核对；最多三名工程师并行是其公开工作方式，不是高流量证明。

## 10. 塔防游戏

[塔防游戏团队契约](https://github.com/kodkod88/tower-defense/blob/e91893a618ec5a63afddef2c0561214cddf4d721/CLAUDE.md)和[任务清单](https://github.com/kodkod88/tower-defense/blob/e91893a618ec5a63afddef2c0561214cddf4d721/docs/BACKLOG.md)说明 Claude Code Lead、玩法、渲染、内容、核心和 QA 的开发职责及依赖。它是前轮已找到的项目，本轮重新核对。队友可直接互发消息；Leader 中继与 Topic 只能作为实验对照。

## 不纳入这 10 项的例子

- [MedRecord](https://github.com/rdevarakond88/medrecord/blob/dc15d4dc89d9b4bb719d52391ed52a82b465eacf/README.md) 是具体移动医疗应用，但文档说明各角色逐个会话顺序执行，并由人操作交接，不作为原生并行 Leader/Worker 案例。
- [另一个任务管理示例](https://github.com/metodievmartin/nextjs-ts-ai-agents-workflow-app/blob/6372cd3847caed7a96d970b08c8efaf273abc1d3/CLAUDE.md)明确称四个角色可由同一个 AI 扮演，不能仅按角色数说成多个并行 Agent。

## 后续筛选和使用

每个候选先验证原作者定义的任务和原生工作方式，记录实际模型、任务和消息；验证后再配置我们自己的跨服务器、Topic 和压力对照。没有实测事件率、Worker/模型容量和链路容量前，不将任何候选定为“通信大概率是瓶颈”。备选清单不改变首测顺序。
