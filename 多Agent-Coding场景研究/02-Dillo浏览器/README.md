## Mac 一键启动

在完整仓库内双击 [Mac/一键启动.command](Mac/一键启动.command)。它是独立文件，也可以单独复制到 Mac 使用：无需选择项目、填写项目地址或另外下载本仓库的脚本。首次运行可能触发 macOS 官方 Command Line Tools 安装及 Codex 浏览器登录，按系统提示完成；Codex CLI 缺失或旧版不支持独立进程时，脚本会从官方 GitHub Release 下载到公共缓存。首次下载需要网络，后续重复利用固定版本缓存。

如果系统提示文件没有执行权限，在终端运行一次 `chmod +x` 加上该文件路径；若被 macOS 安全机制拦截，可在 Finder 中右键选择“打开”。运行会调用账户的真实模型，产生模型用量和可能的费用。脚本不需要 Android 模拟器，不修改原有项目、不推送开发结果。

若模型预检发现已有 API Key 无效，脚本会切换到公共缓存中的实验专用 Codex 登录目录，清除本次进程继承的 API Key，按官方提示完成登录并重试；原有 Codex 登录和系统环境变量不会被修改。专用登录不继承原有 Codex 配置，后续可复用；如果账号仍无模型访问权限，报告会显示实际错误。

为兼容缺少 `codex-code-mode-host` 的独立版，实验显式启用标准 shell 工具并关闭 code mode。正式计时前会用相同配置实际运行命令并核验结果；如果工具仍不可用，会在准备阶段给出错误和检查日志，不将此次运行计入正式任务。

**实现架构：** 一个真实 Codex CLI Leader 按任务启动五个独立的真实 Codex CLI Worker，使用本地 HTTP 路由服务执行 Leader 分派、Worker 回报与 Topic 分发。每个 Agent 是独立进程和工作目录，以便采样进程树 CPU；Worker 间直接发送被该路由服务拒绝。这个模式是本实验的 Codex CLI + 自建中继，**不是 Codex 内置子 Agent 原生传输路径**。初始进程提示词、模型请求和文件操作不经中继，分别记录或标记未覆盖。

为兼容 Codex 沙箱对 Git 元数据的保护，Worker 通过本地服务请求提交；服务只提交该角色允许的文件，Leader 请求服务将本地提交集成到 Leader 副本，Git 执行和等待锁的时间分别记录。Leader 可在 Worker 仍运行时转发反馈；当前每个 Worker 启动一次，退出后的修复由 Leader 在集成副本中完成，尚不支持恢复同一 Worker 会话。

终端每 15 秒显示准备/开发进度，正式开发时间从 Leader 启动开始，包含最终独立验证，不含下载、安装、登录、模型预检和上游基线。结果保存在 `~/codex-agent-experiments/browser01-时间戳/`；公共源码和工具保存在 `~/codex-agent-experiments/工具缓存/`，旧批次可以单独删除。每次自动打开 `实验报告.html`，并保留 `实验状态.json`、`准备过程.log`、`测试/` 和 `记录/`。

报告包含：

- 各 Agent 的 PID、运行时长、采样 CPU 平均/峰值与 RSS 峰值；另列本地路由和采样进程。CPU 是进程树近似，不包含远端模型或可能存在的共享外部服务。
- 记录物理/逻辑 CPU、物理内存、正式任务前的系统内存快照；在 macOS 上约每 5 秒记录 `vm_stat` 和 swap 原始计数。
- 按发送方、接收方及 Topic 的真实消息正文、字节、路由事件，以及发送到服务、路由入队、等待领取、客户端接收等可配对耗时。接收确认由本地客户端发出，不代表模型已经理解内容。
- 每秒路由消息和 HTTP JSON 正文字节、全周期平均速率和单秒峰值；这些是本机应用层数据，不是物理网卡、真实跨服务器链路或 TCP 包速率。
- 两方向分别记录入队正文的每秒字节和副本数，保留未领取消息；逐接收者确认数据仍在消息明细。数据中心链路重放和滑动窗口分析尚未实现。
- Codex 工具事件耗时、各 Agent 生命周期、独立验证耗时和可获取的模型遥测。脚本尝试将 Codex OTLP 指标发送到本地收集器；如果当前版本或服务端不提供模型推理指标，报告会标记不可得，不会将 Agent 总耗时、等待或网络耗时冒充推理时间。
- 上游回归、独立验收、安全测试和本机 HTTP 头部测试。只有五个 Worker 均实际启动、完成、被 Leader 领取回报，W1–W4 均有各自范围的已提交代码，至少两个 Worker 确认接收共享契约 Topic，最终审查交互和必要功能测试均通过，才标记核心任务完成。这个 HTTP 测试不等同完整浏览器 GUI 端到端测试。

完整会话、代码和消息可能包含敏感信息，默认仅保存在用户自己的实验目录。取消任务可在终端按 `Ctrl+C`；脚本会停止它启动的进程并保留已有记录。

## 真实开发任务：下载文件名支持 UTF-8 扩展参数

在固定版本中，[`src/misc.h`](https://github.com/dillo-browser/dillo/blob/6856c5016de8cc15d077ec8d785bac1a38b4a813/src/misc.h) 提供 `Content-Disposition` 解析，[`src/cache.c`](https://github.com/dillo-browser/dillo/blob/6856c5016de8cc15d077ec8d785bac1a38b4a813/src/cache.c) 在根请求中解析头部并将文件名交给保存流程，[`src/uicmd.cc`](https://github.com/dillo-browser/dillo/blob/6856c5016de8cc15d077ec8d785bac1a38b4a813/src/uicmd.cc) 接收建议文件名。现有 [disposition 单元测试](https://github.com/dillo-browser/dillo/blob/6856c5016de8cc15d077ec8d785bac1a38b4a813/test/unit/disposition.c) 包括同时存在 `filename` 和 `filename*` 的情况，当前预期使用普通文件名。

本实验要求实现并验证：

1. `attachment; filename="fallback.txt"; filename*=UTF-8''foo-%c3%a4.txt` 应使用 **`foo-ä.txt`**；仅有合法 UTF-8 `filename*` 时也能正确产生文件名。参数名大小写、参数顺序及原有普通 `filename` 行为应有覆盖。
2. 无效百分号转义、无效 UTF-8、空值或不支持的字符集不得产生不安全名称；存在合法普通 `filename` 时按约定回退，没有可用值时交回原有默认命名路径。
3. 编码后的路径分隔符、`..`、控制字符及 NUL 不能在解码后绕过现有的文件名安全处理；不得覆盖目标路径之外的文件。安全行为需用测试举证。
4. 适配现有 HTTP 头部至保存建议名的实际调用路径，保持向后兼容。原测试中上述双参数行的预期因本功能改变而更新，其余旧行为须回归通过。
5. 附上独立测试、错误与边界说明，并完成 Lead 集成。**最终通过条件包括功能及必要的集成验证；单个解析器测试通过不等于浏览器端到端通过。**

这是依据 Dillo 实际代码和测试提出的实验开发任务，不声称是 Dillo 官方 issue 或 Cursor 原始任务。任务不要求 Worker 互相发送无用的大段内容：传递变更、边界、测试失败和结果等实际需要的信息。

这个功能范围适合先验证完整的开发、通信观测与报告流程；一次小功能开发的消息率不能代表大型浏览器项目或数百 Agent 协作。验证通过后，计划增加 Dillo 自带的渲染回归修复任务：[`test/html/Makefile.am`](https://github.com/dillo-browser/dillo/blob/6856c5016de8cc15d077ec8d785bac1a38b4a813/test/html/Makefile.am) 已将 `span-padding.html`、`margin-auto.html`、`float-img-justify.html` 标为预期失败。固定基线后再分别分析和修复这些真实用例，围绕共享布局代码、独立测试和集成进行分工；不预先假定它们会产生大量通信。渲染对照需要额外的图形测试依赖，准备成功并实际运行后才统计结果。

## 预设分工与依赖

| 角色 | 真实工作 | 与其他角色的依赖 |
|---|---|---|
| Lead（Codex 主 Agent） | 冻结任务边界、分派、处理阻塞、集成补丁并运行最终验证 | 收集各 Worker 结果，决定是否返工和集成 |
| W1 解析实现 | 实现扩展参数解析、解码、回退和与现有 API 的兼容 | 接收 W2、W3 对测试和安全边界的反馈 |
| W2 回归测试 | 修改现有 disposition 测试，覆盖普通值、扩展值、冲突及回退 | 对照 W1 的接口契约；实现合并前可出现预期失败 |
| W3 安全与边界 | 审阅解码后文件名的安全性；在独立测试文件中覆盖遍历、NUL、控制字符、无效编码 | 发现问题报告 Lead，Lead 路由 W1 修复；测试结果进入集成门禁 |
| W4 HTTP 到保存建议名验证 | 检查 `src/cache.c` 到保存调用链；构建独立的 HTTP 头部/建议名集成验证，必要时提出最小修复 | 依赖 W1 的契约和 Lead 集成结果；区分真实 GUI 验证与测试替身 |
| W5 独立审查 | 核对规范、旧行为、测试证据与合并结果，给出可复现的问题或通过依据 | 汇总 W1–W4 的结果；Lead 根据发现分配修复和重测 |

初始计划 **1 个 Lead + 5 个 Worker**，不是保证 Codex 实际会启动该数量。每个 Worker 指定独立 Git worktree 或独立工作副本、专属分支和写入范围；它们是普通本地目录，不是虚拟机。Lead 通过补丁或提交集成，检查冲突、来源和测试；不能把“已创建 Agent”当作“已完成开发”。如果平台会话或模型资源不能支持 5 个并发，记录实际并发、排队和失败，不伪造成功。

Topic 对照可根据实际依赖使用 `download/contract`、`download/parser`、`download/security`、`download/integration`、`download/tests` 等主题；订阅者随负责模块及 Agent 状态变化，变更和取消订阅都要记录。只有对任务确有用的事件才发布；Worker 仍负责真正写代码、运行测试和审查。

## 实验顺序

### A. 独立 Codex 会话的真实开发

1. 自动拉取并校验固定 Dillo 版本；以只读来源缓存建立独立批次和 Worker 目录。检查 Git、C/C++ 编译工具、Codex 及登录；使用当前账户和 Codex 默认模型，先做实际连接检查。缺少依赖时自动准备可用的本地缓存；必须由用户处理的官方登录或系统权限在界面解释并引导。
2. 在首次正式开发前完成基线测试和环境准备；准备过程实时显示当前阶段、最近输出和已耗时，不计入正式开发耗时。
3. 启动真实 Codex Leader，由 Leader 通过本地服务启动五个独立的 Codex CLI Worker，传入上面的任务与写入范围。捕获各个独立会话事件、任务分派、追加消息、可识别结果、实际变更、测试和错误。
4. Lead 集成后重跑单元测试和必要的集成验证。记录工作是否完成、每个 Worker 是否实际工作、主线程和子会话 ID、实际并发峰值与失败原因。单次失败保留日志，不能标记成功或把缺失消息当作零。

本次一键入口使用独立 Codex CLI + 实验路由，对照 Codex 内置子 Agent 原生协作的基线仍需另行实现；两者不能合并统计。

### B. 本地 Leader Topic 中继对照

当前一键入口已包含本机轻量软件协调服务，支持订阅、取消订阅、按 Topic 发布、记录每个接收者、领取和确认；所有 Worker 是实际 Codex CLI，服务不代替 Agent 开发。重试/持久化和独立原生协作对照尚未实现。

当前实现通过本文件的内部客户端和本地 HTTP 服务传递消息，不依赖 MCP。路由拒绝 Worker 直接发给其他 Worker；进程初始提示和 Codex 内部工具调用不通过本路由，不能称为全部流量。事件 ID 关联发送、服务入队、领取和确认；不同接收者分别记录。当前不保证消息持久化、去重或重启后恢复。

### C. 实际轨迹驱动的容量测试

从 A、B 分别提取经过核对的到达间隔、正文大小、事件类别及订阅变动；先测一个真实工作流，按环境承载逐步增加同时工作流和 Agent，记录实际数量，不预设 1,000 Agent 可以在一台机器运行。之后可单独重放已采集事件，寻找软件路由和包处理上限；重放器不是 Coding Agent，重放速率不是自然开发速率。默认先进行一次真实任务；对照及重复次数后续按模型配额和资源条件安排。

同一条件采集 Lead/协调服务 CPU 和内存、Worker 进程可见资源、构建测试资源和模型错误/排队；模型远程服务资源不能从本机 PID 推断。逐级增加负载时，比较吞吐、P50/P95/P99、失败和队列，同时检查 Agent、模型、编译和存储仍有余量；通过改变 Leader CPU、链路或路由实现做因果对照，才判断通信处理是否为瓶颈。

跨服务器和交换机卸载放在本地基线之后。届时记录真实拓扑、链路容量、时钟同步、订阅规则更新、重复/乱序、故障恢复及一致性；不同部署保持任务和语义一致。

## 测什么、能得出什么

| 指标 | 获取方法 | 结论口径 |
|---|---|---|
| Leader/Worker 消息正文 | 按关联会话 ID 与协作工具事件提取，分别统计方向、事件和 UTF-8 字节；人工核对遗漏和重复 | 可识别消息正文，不是所有流量，调用也不保证送达 |
| 本地 Topic 消息与字节 | 对照 B 的协调服务记录事件 ID、发布/订阅/逐接收者分发、载荷及协议序列化字节 | 实验新增中继的可观测数据，不能直接算成原生 Codex 流量 |
| 延迟拆分 | 同机单调时钟记录客户端调用、服务接收、路由、排队、发出、领取和确认；保留请求 ID | 服务端可观测区间与客户端往返分开；模型推理、Worker 工作、`wait` 不称为网络延迟 |
| 实际网络包及线速字节 | 当前脚本尚未实现抓包；报告给出本地 HTTP JSON 正文字节 | 不等于 TCP 包、协议开销、物理网卡或交换机链路字节，标记不可得 |
| Agent、进程与资源 | Codex 会话树、状态和 `ps` 采样；必要时记录构建子进程 | Agent 不一定各占一个 PID，RSS 相加可能重复，共享模型资源不在本机采样内 |
| 完成情况 | 代码 diff、每个工作区和测试日志、原生结果与退出状态 | 功能与集成验证独立核对；缺失证据或失败须列明 |

正式开发总时长从真实 Codex 主任务启动计至结束；依赖下载、环境与项目准备、基线测试和报告生成不计入。报告包括事件数/字节、每方向与阶段、每 Agent 的可归属消息、速率、峰值及可配对延迟分布；低样本或缺少精确时间戳明确标注，不猜测网络耗时。

## 运行目录和一键入口的设计

现提供**本应用一个双击脚本**，无需让用户选择项目；默认记录到 `~/codex-agent-experiments/`。共享缓存保存固定版本仓库镜像、工具和可复用依赖；每次独立目录存放 worktree、任务、日志、状态、测试、补丁及报告。历史批次可单独删除，公共缓存不放到批次中。脚本应在终端持续展示阶段、已耗时、最近输出和故障原因；可复用已有缓存，不因准备失败生成看似完成的报告。

```text
codex-agent-experiments/
├── 工具缓存/                      # Git 源缓存及必要工具；跨批次复用
└── browser01-时间戳/              # 本次实验独立结果
    ├── 应用/                      # Lead 工作目录
    ├── workers/                   # Worker 独立 Git 副本和分支
    ├── 记录/                      # 原始 Codex 事件、关联会话、通信明细
    ├── 测试/                      # 原版和最终验证日志
    ├── 实验状态.json
    └── 实验报告.html
```
