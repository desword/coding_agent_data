# 01：Now in Android 多 Agent 测试

双击 [一键测试.command](一键测试.command) 启动；不需要选择项目。脚本固定下载 Google 的 [Now in Android](https://github.com/android/nowinandroid) 和公开的 [Android Bug Priority Tree](https://github.com/ChrisThoma/android-bug-priority-tree) 流程，构建应用并启动两个独立 Android 模拟器，再让 Codex Leader 分派真实的设备测试、问题确认、修复及验证任务。应用与公开流程的组合、两台设备和任务分工是本实验配置；不能说公开项目已经验证过这个组合，也不能假定 Codex 一定会遵守所有分工。

## 运行前

- macOS 下载后双击脚本；Linux 可以运行 `python3 一键测试.command`。需要联网、Git、Python 3.9+ 和可以使用 Codex 的账号。缺少 Python 或 Git 时，需要先安装；未登录 Codex 时按窗口提示登录。模型调用可能产生费用。
- 脚本会优先复用本机符合要求的 JDK、Node.js 和 Android SDK；缺少时自动下载并校验 JDK 21、Node.js 22、Google 的 SDK 命令行工具，以及应用所需的模拟器组件。Android SDK 的许可协议如出现，请在窗口中阅读并选择。工具缓存保存在 `~/codex-agent-experiments/工具缓存/`，后续运行可复用；如果发现已有可写 Android SDK，也可能向该 SDK 安装缺少的组件。
- 计算机需要能够启动 **两台**启用了硬件加速的 Android 模拟器，并有足够内存与磁盘空间。首次运行可能下载多个 GB；安装和构建耗时较长。Agent 阶段最多运行两小时，请保持窗口打开；按 Ctrl+C 中断。
- 网络无法访问下载源、系统不支持硬件加速或权限不足时，脚本会在报告中标明失败；软件自动安装不能代替硬件支持。macOS 首次打开程序如被系统阻止，可在 Finder 中右键脚本选择“打开”。

脚本只操作新下载的独立应用副本，并为本次运行单独创建模拟器与结果目录；运行结束会关闭它启动的模拟器。它不会推送应用代码。设备工具使用固定版本 Mobile MCP，Codex 的模型和账号沿用本机配置。Agent 使用可写工作区沙箱，并允许网络访问以连接本机设备和获取构建依赖。

## Codex 认证检查

启动时会先发送一条简短的 Codex 请求，验证模型是否可用，然后再启动模拟器和构建；这一请求不计入正式实验，可能产生少量模型使用量。如果检测到不适用于 OpenAI 官方接口的 API 密钥，脚本会为本实验准备独立的 Codex 登录，并按提示打开浏览器；该登录保存在工具缓存中，不会覆盖已有的 Codex 登录或系统环境变量。需要使用具备 Codex 权限的账号完成验证。其他认证、权限或网络错误会显示实际诊断，不会自动改换服务商。

## 运行时查看进度

窗口会显示六个阶段、各命令实时输出及阶段耗时；下载时会尽量显示已下载大小。没有新输出时，每 15 秒显示命令是否仍在运行、已耗时和上次输出时间；Codex 阶段也显示事件文件大小和最新事件类型。进程仍在运行并不保证任务正在取得进展；显示的超时上限也不是预计完成时间。

若正在运行的是旧版本，可另开终端使用 `tail -f` 查看该次实验目录中的 `准备过程.log`；更新脚本不会改变已经启动的进程。

## 结果在哪里

正式开发计时从启动 Codex 多 Agent 任务开始，到该任务退出为止；不包括依赖下载、模拟器准备、应用构建、基线测试和报告生成。如果正式任务未启动，报告会显示没有有效开发耗时。调用耗时可以重叠，不能直接相加作为总耗时。

每次运行都在 `~/codex-agent-experiments/android01-时间戳/` 生成结果。Mac 上结束时会尝试自动打开 `实验报告.html`。失败或中断也会保留报告和已经产生的日志，报告会显示未完成原因。

- `实验报告.html`：正式 Codex 多 Agent 任务耗时、可识别消息条数和正文 UTF-8 字节数、方向、消息摘录、工具调用耗时、可配对的发送—接收时间、设备和证据说明。
- `记录/消息明细.csv` 和 `记录/sessions/`：可识别的协作消息和原始会话；`记录/调用耗时.csv` 是工具调用到返回的时间。
- `投递时间明细.csv`：仅在原始诊断日志提供可匹配的通信 ID、发送与接收事件时才有有效样本；如为空或不可配对，无法得知投递耗时。
- `设备资源.csv`、设备和基线测试日志、`准备过程.log`：用于检查设备启动、基线测试和资源情况。

**解读限制：**正文 UTF-8 字节数不是网络链路流量，未包含协议开销、模型请求、共享上下文或文件内容；解析器也可能漏掉未支持格式。发送到接收的时间包括本地调度，不能当作纯网络时延。`wait` 包括 Agent 工作与模型耗时，不能当作通信耗时。设备已启动、基线测试通过、子会话存在都不证明 Worker 按要求完成了设备测试，需要核对原始会话及其设备操作记录。缺少有效投递样本或对照时，不能判断通信是否为主要瓶颈。报告、日志和会话可能包含源代码、任务内容与敏感数据，分享前请检查。

目前已完成的验证是采集器已有测试、模拟依赖的流程测试及 Mobile MCP 的启动和工具列表检查；尚未在具备 Android 模拟器和可用 Codex 模型权限的机器上完成真实端到端运行。若 Codex 阶段失败，报告会优先显示事件文件或错误日志中的原因；完整信息见 `记录/codex-events.jsonl`、`记录/codex-stderr.log` 和 `Codex运行.log`。分享日志前请检查是否包含敏感内容。
